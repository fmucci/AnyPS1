# 05 — Known pitfalls (already hit; do not rediscover)

| # | Symptom | Cause (observed) | Fix |
|---|---------|------------------|-----|
| 1 | `7zz x GAME.rar` asks for a password, then `ERROR: Unsupported Method` and leaves **0-byte** `.bin/.cue` | Archive is RAR5 with AES + method `v6:m3:32M`; 7-Zip 26.04 can't decode it. The 0-byte files look like success — they are not | Use `unar -p "$PS1_ARCHIVE_PASSWORD" -o <dir> FF9.rar` |
| 2 | `brew install rar` fails | Cask disabled (Gatekeeper) as of 2026-09-01 | Use `unar` |
| 3 | `7zz l "GAME.bin"` → "Cannot open the file as archive" | It's raw `MODE2/2352`; 7-Zip doesn't parse the sector framing | `tools/iso_extract.py` reads user data at byte offset 24 of each 2352-byte sector |
| 4 | REA `open_binary` on `SLUS_012.51`: `unsupported binary format` | `PS-X EXE` isn't a format REA knows | `tools/psx2elf.py` wraps it as ELF |
| 5 | Ghidra lane rejects the ELF: `requires EF_MIPS_ARCH_32R2`, then `inspected ABI flags record`, then `32-bit GPR/CPR1 and no CPR2`, then `double-precision or FPXX ABI only` | REA's verified lane is narrow | Already encoded in `psx2elf.py` (flags `0x70001000`, abiflags isa32/rev2/gpr32/cpr1 32/fp=1). If you change it, re-run all five conversions and re-check the `fb2.elf` sha256 |
| 6 | `binary_session` / `list_strings` "exceeds maximum allowed tokens" | Output is 90–220k chars | It's saved to a file; use `jq` on it |
| 7 | `search_strings {query}` / `list_strings {limit}` validation errors | Wrong parameter names | `pattern`; `list_strings` has no limit param |
| 8 | Shell `java` is 17 but Ghidra works | REA uses `JAVA_HOME` from its MCP entry, not the shell | Don't "fix" the shell JDK; check the MCP `env` |
| 9 | Changing working dir to the data dir for a script | Interpreters import from cwd; extracted data is untrusted | Run scripts by absolute path with `python3 -I`; never `cd` into `og-files/` to run code |
| 10 | Extracted ISO files all look right but sizes of `.DAT/.XA` might be off | `iso_extract.py` copies only the 2048 user bytes per sector; XA/STR files are Mode2 **Form 2** (2324 bytes/sector) so those files are **not** faithful copies | OBSERVED limitation of the extractor (it has no form detection). Do not analyse `XA_FR/*`, `VIDEO*/*` from `og-files/disc` until the extractor is extended to read raw 2352-byte sectors for those files. Executables and level data are Form 1 in the usual layout, but **verify per file** before trusting (compare against the raw `.bin` at the file's LBA) |
| 11 | `search_strings` with a regex returns `[]` | Default `mode` is literal | Pass `mode: "regex"` |
| 12 | `xrefs`/`procedure_*` take different parameter names | `xrefs {address}`; `procedure_pseudo_code/assembly/callers {procedure}` | Check the schema error, it names the expected key |
| 13 | Ghidra pseudo-code shows a call with fewer arguments than the callee really received (e.g. `FUN_80011098(n)` while the caller passed buffer and mode) | Argument registers `a1..a3` flow through a wrapper untouched; the decompiler drops them when the wrapper never reads them | For any wrapper that calls another function, read the **assembly** and check which of `a0..a3` are written before each `jal`. Found in finding 0004; it had produced a wrong inference in 0003 |
| 14 | `procedure_assembly`/`resolve_containing_procedure` on a valid code address returns `No procedure exists at the requested address` / `not_in_procedure` (e.g. `0x8007b8d4`) | Ghidra defined no function there: runs of tiny leaf functions without a stack prologue (the libgpu `Set*` initialisers at `0x8007b8cc..0x8007bab0`) are left as undefined code | Decode the words yourself from `og-files/disc/SLUS_012.51` (offset `0x800 + addr − load`), or use `tools/scan_prims.py`. Its function-start guess (`addiu sp,-N` or the word after `jr ra`+delay slot) can be off by a few words: verify the real entry in the disassembly before quoting a caller count (finding 0008: guess `0x80079030`, real `0x80079028`) |
| 15 | A binary built with `-fsanitize=address` hangs at start with no output; `timeout` is not found | On this macOS toolchain the ASan runtime deadlocks in its own init (`AsanInitInternal -> InitializeShadowMemory -> get_dyld_hdr -> malloc -> AsanInitFromRtl -> StaticSpinMutex::LockSlow`, seen with `sample`; finding 0018); macOS has no `timeout` | Use `-fsanitize=undefined`; bound risky runs with `perl -e 'alarm 25; exec @ARGV' cmd` |
| 16 | Python process dies with `Segmentation fault` inside a `ctypes` call into `build/libps1io.*` | A `ctypes` function without `argtypes` passes a Python int pointer as a 32-bit `int` (the pointer is truncated) | Declare `argtypes`/`restype` for every function in `oracle.load_io_lib()`; run with `python3 -X faulthandler -I ...` to find the call |
| 17 | A device model runs the game's library ~1.6x too fast and one movie stalls near its end (`Retry` printed in a loop, `StHEADER` ring full of finished frames) | The CD data-rate credit was added on every `cd_fire` call, and the runtime calls it up to four times per virtual frame | Add rate credit once per tick (`io_vblank_tick`), not per call; check device rates (sectors per 60 Hz tick) against psx-spx before debugging the consumer |
| 18 | `unknown GP0 command 0809a9b0` (a tag word of an ordering table reaches GP0) | GP0 `04h..1Eh`, `E0h`, `E7h..EFh`, `03h` are one-word NOPs (psx-spx "GPU Other Commands"); a table node whose length is one word too long sends the next tag as data | Treat them as NOPs; do not "fix" the game's list |
| 19 | `indirect call to XXXXXXXX: no generated function or HLE hook is registered there` right after a `jr` through a table indexed by a small value | The jump-table recogniser only accepted `addu`; the code used `add` | `tools/recomp/funcs.py` now accepts both; regenerate `docs/symbols/*.csv` after changing the recogniser |
| 20 | Differential trace differs only in `a1..a3` of an HLE line inside a callback | `Oracle.call_guest` cleared a0..a3, the C `guest_call` left the interrupted code's values | Both pass zeros; when adding any host-to-guest call, set all four argument registers explicitly in both implementations |
| 21 | C99/UBSan `left shift of negative value` in new fixed-point code | `(t << 12)` with a negative nibble | Multiply (`t * 4096`) instead of shifting signed values |
| 22 | `timeout` and `sleep N` in a tool call are rejected / not found | macOS has no `timeout`; long foreground `sleep` is blocked | `perl -e 'alarm N; exec @ARGV' cmd` for a time limit; poll with `until grep -q marker file; do sleep 5; done` for background work |

Add new rows when you hit something. Include the exact error text and what you verified.
| 23 | A screen stays black (or a sequence never advances) although the program keeps running and the CPU is not stuck in a lock | A busy-wait on a hardware status bit our model never changes (here GPUSTAT bit 31, odd/even field) | Find the spinning loop with `PS1_DUMP` on the reported pc, decode the status read, and make the model produce the bit; compare with the reference emulator |
| 24 | Gameplay is silent although video/input work and the SPU unit tests pass | A timer interrupt the game relies on (root counter 2 at 100 Hz drives its sound sequencer) was never raised, so no voice is keyed on | Count key-ons (`PS1_SPUKON=1`) and compare audio RMS per second with the reference emulator; check timer register writes with `PS1_GPULOG=1` (TMRn.r lines) |
| 25 | A program ignores input (or a feature never starts) although the value reaches the game's buffer | A phase-2 `Null` hook replaced a start-up routine that registers a vblank/event callback (here the credits' pad callback), or discovery never found the callback (no prologue) | Compare with the reference emulator's PC list (`tools/ref_emu`), check which `Null` hooks exist in `tools/recomp/hooks.csv`, remove them once the BIOS layer exists, and add unfindable callbacks to `tools/recomp/roots.csv` |
