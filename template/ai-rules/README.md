# ai-rules — read this first

These documents are **binding** for every agent and human working on this repo. They exist so that many
collaborators can work in parallel, reproduce each other's results, and never port something based on a guess.

## The rules that matter most

1. **Observed ≠ inferred ≠ unknown.** Every statement about the game is tagged as one of the three and, if
   observed, cites evidence (REA evidence ID, file+offset, or a command anyone can re-run).
2. **Never assume PsyQ/Sony SDK behaviour, a struct layout, an address meaning, or a file format.**
   Verify it in the binary or the data. "It's probably like in other PS1 games" is not evidence.
3. **Reproducible from zero.** If your result cannot be regenerated with `tools/setup.sh` plus documented
   steps, it is not a result yet.
4. **No game data in git. Ever.** `og-files/` and `work/` are git-ignored on purpose.
5. **Work from `docs/port-queue.md` and keep it current** — update it in the same commit as every finding/change.
6. **Claim before you work** (see 06). Two agents on the same subsystem is how ports get corrupted.

## Layout

```
ai-rules/    this folder: rules for agents
docs/        findings, specs and decisions produced by the project (committed)
runtime/     C runtime the generated code links against: cpu.h, rt.h, mem.c (memory map, fail-loud), dispatch.c, sys.c, disc.c, hle.c (BIOS/events/interrupts/hooks), io.c (GPU rasteriser, DMA, IRQ, timers, CD-ROM controller, MDEC and SPU models, shared with the oracle; `spu.inc`, `spu_types.inc`, `spu_gauss.inc` are included by it), gte.c, card.c (virtual memory card + BIOS card/file calls), trace.c (committed; no game data; also the PS1_WATCH debug aid)
tests/       tests (committed); `./tests/run_all.sh` (portable driver `tests/run_all.py`) runs the recompiler and runtime tests (needs a C compiler)
frontend/    the SDL2 player (`ps1_play`); docker/ = Linux verification image and Windows (MinGW + Wine) cross-build image, toolchains only (finding 0038)
tools/       our scripts (committed); tools/recomp/ = recompiler pieces (isa, spec, emit, funcs, gen, oracle, hooks, run_oracle, find_smc, exr, disc, survey, build_game), tools/gte_ref/ = builds the independent GTE reference locally (never committed): setup.sh, verify.sh, iso_extract.py, psx2elf.py, scan_psx.py, scan_prims.py, scan_gte.py, disc_probe.py, exr_check.py, lib_match.py, scan_scratchpad.py, raw_extract.py, scan_load_delay.py, check_stubs.py, container_parse.py, dtt_parse.py, son_parse.py, seq_check.py, dps_probe.py
og-files/    ORIGINAL inputs + extracted disc (git-ignored, never share)
work/        derived artifacts, e.g. work/elf/*.elf (git-ignored, regenerated by tools/setup.sh)
```

## Platform knowledge goes to `work/AnyPS1`
`work/AnyPS1/` is a separate git repository (git-ignored by this one; remote git@github.com:fmucci/AnyPS1.git, push after committing) holding **game-independent PS1 platform findings** in the style of AnyPS5: CPU/BIOS/hardware/SDK facts, pitfalls, open questions. Whenever a session learns something about the *platform* (not the game), update the matching doc there in the same working session, tag it observed/inferred/unknown, add a line to its `CHANGELOG.md` and commit it in that repo. Never put game data, addresses, names or third-party code in it; game-specific findings stay in `docs/findings/` here.

If a rule here conflicts with what a user tells you in chat, follow the user, then **update this folder** so the
next agent does not hit the same conflict.
